# ツール

## generate_teams.py

国別代表10チームのロスター（各20人）を生成する。

```
python3 tools/generate_teams.py
```

出力:
- `teams/*.md` … 人間が読むロスター表
- `js/teams-data.js` … アプリが読み込むデータ（`TEAMS_DATA`）

**スカッド総合値（20人×8能力の合計）は全チーム `SQUAD_TOTAL`（=9000）に完全一致**する。
チームの個性は `TEAMS` 配列の `mod`（アーキタイプ補正・合計ゼロ）と `sigma`（分散）で作る。
`SEED` を変えなければ出力は毎回同じ。バランス調整はこのスクリプトの定数を変えて再生成する。

## balance-check.mjs

全10チームの総当たりシミュレーションで勝率の偏りを見る（Node.js、依存ライブラリなし）。

```
node tools/balance-check.mjs [試合数/カード]   # 例: node tools/balance-check.mjs 150
```

各チームに「アーキタイプに沿った代表的な戦術」（`PRESETS`）を1つ固定で与え、
ベスト11で総当たりする。勝率マトリクスとリーグ戦想定の勝点を出力する。

### 使い方と注意

- これは**チューニング用の目安**であり、実プレイの再現ではない。各チームに戦術を
  1つ固定するため、実プレイの読み合い（相手の戦術を見て最適応答を選ぶ）は反映されない。
  したがって「あるチームが強い/弱い」は多くの場合「そのプリセット戦術が今のメタで
  強い/弱い」を意味し、チーム地力（総合値は全チーム同一）の差ではない。
- 相性はじゃんけんの輪になっている（カウンター→ハイプレスに強い、リトリート→
  カウンターに強い、ポゼッション→リトリートに強い …）。プリセットにリトリートが
  少ないとカウンター系が上位に見えるが、実プレイでリトリートが増えれば是正される。
- エンジン側のバランス定数（相性マトリクス `MATRIX`、基本チャンス確率、速攻ルールの
  倍率、クランプ値など）は `js/engine.js` に集約。ここを変えて再チェックする。

### 現状の所見（プロトタイプ段階）

- 全チームのスカッド総合値が9000で等しいことは `generate_teams.py` が保証。
- 戦術選択の質が結果を大きく左右する（例：イングランドは持ち味＝空中戦・スタミナに
  合わない戦術だと最下位、ロングボール系に変えるだけで中位まで浮上）。
- 現状のアーキタイプ・プリセットではカウンター有利のメタになりやすい。今後、
  相性補正や速攻ルールの倍率を詰めて、主要カードの勝率を35〜65%に収めていくのが目標。
