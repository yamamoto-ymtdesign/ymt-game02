# 戦略ファイル書式仕様

戦略ファイルは Markdown（.md）またはプレーンテキスト（.txt）で記述する。
システムは見出し（`##`）と `キー: 値` の行を読み取る。この仕様に従っていれば、
コメントや意気込みなどを自由に書き足してもよい（パーサーは無視する）。

ひな形は [strategies/template.md](../strategies/template.md) を参照。

## ファイル全体の構造

必須セクション（`##` 見出し）は次の5つ。順不同でよい。

1. `## チーム情報`
2. `## 基本戦術`
3. `## チーム能力`
4. `## 状況別指示`（指示が0個でもセクション自体は必須）
5. `## 切り札`

任意セクション：`## ハーフタイム指示`、`## チーム紹介`（自由記述、判定に影響しない）

## 1. チーム情報

| キー | 制約 |
|---|---|
| `チーム名` | 1〜20文字。実況で使われる |
| `監督名` | 1〜20文字 |

## 2. 基本戦術

すべて必須。値は選択肢から**完全一致**で選ぶ。

| キー | 選択肢 | 効果の概要 |
|---|---|---|
| `フォーメーション` | `4-4-2` / `4-3-3` / `3-5-2` / `4-2-3-1` / `5-3-2` | 中盤補正・攻守バランス（下表） |
| `攻撃スタイル` | `ポゼッション` / `カウンター` / `サイドアタック` / `ロングボール` | 相性マトリクス参照 |
| `守備スタイル` | `ハイプレス` / `ゾーン` / `リトリート` / `マンマーク` | 相性マトリクス参照 |
| `ライン設定` | `高い` / `普通` / `低い` | 高い=攻撃的だが裏に弱い |
| `テンポ` | `速い` / `普通` / `遅い` | 速い=支配権+だがスタミナ消費+ |

### フォーメーション補正表

| フォーメーション | 中盤スコア | チャンス確率 | 被チャンス確率 |
|---|---|---|---|
| 4-4-2 | ±0 | ±0 | ±0（バランス型） |
| 4-3-3 | ±0 | +2% | +2%（攻撃型） |
| 3-5-2 | +2 | ±0 | +1%（中盤支配型） |
| 4-2-3-1 | +1 | ±0 | −1%（堅実型） |
| 5-3-2 | −1 | −2% | −4%（守備型） |

## 3. チーム能力

6項目に **合計ちょうど36ポイント** を配分する。各項目は **1〜10の整数**。

| キー | 主な影響 |
|---|---|
| `攻撃` | チャンス確率・ゴール確率 |
| `守備` | 被チャンス確率・被ゴール確率 |
| `スピード` | カウンターの威力、裏抜け対応 |
| `テクニック` | 支配権判定（中盤スコア） |
| `スタミナ` | ティックごとの消費軽減。切れると総崩れ |
| `メンタル` | 終盤・ビハインド時の補正、PK戦 |

書式例：

```
攻撃: 8
守備: 5
スピード: 6
テクニック: 7
スタミナ: 6
メンタル: 4
```

## 4. 状況別指示（0〜3個）

箇条書きで `IF 条件 THEN 変更` の形式。条件は `AND` で最大3つまで連結できる。

```
- IF 後半 AND ビハインド THEN 攻撃スタイル=ロングボール, ライン設定=高い
- IF 終盤 AND リード THEN 守備スタイル=リトリート, テンポ=遅い
```

### 使える条件

| 条件 | 意味 |
|---|---|
| `前半` / `後半` / `終盤` | 終盤は70分以降 |
| `リード` / `同点` / `ビハインド` | 現在のスコア状態 |
| `2点差リード` / `2点差ビハインド` | 2点以上の差 |
| `スタミナ30未満` | 自チームの疲労 |

### 変更できる項目

`攻撃スタイル` / `守備スタイル` / `ライン設定` / `テンポ`（カンマ区切りで複数同時変更可）

### 発動ルール

- 各ティックの開始時に上から順に条件を評価し、**合致した指示をすべて適用**する
- 条件が解消されたら（例：同点に追いついた）、基本戦術に戻る
- 矛盾する指示が同時に合致した場合は、**後に書かれた指示**が優先される

## 5. ハーフタイム指示（任意、最大1つ）

後半開始時に**無条件で**適用される変更。状況別指示と同じ変更項目が使える。

```
変更: テンポ=速い
```

不要なら `変更: なし` と書くか、セクションごと省略する。

## 6. 切り札（必須、1つ選択）

| キー | 内容 |
|---|---|
| `種類` | `スーパーサブ` / `ギアチェンジ` / `鉄壁モード` / `パワープレー` |
| `発動条件` | 状況別指示と同じ条件書式。1試合1回、条件を満たした最初のティックで発動 |

```
種類: パワープレー
発動条件: IF 終盤 AND ビハインド
```

※ `パワープレー` は80分以降でないと発動しない（条件が先に満たされても待機する）。

## 7. バリデーションルール（受理条件）

システムは読み込み時に以下をチェックし、違反があれば**理由つきでエラー**を返す。

1. 必須セクション5つがすべて存在する
2. 基本戦術5項目がすべて選択肢内の値である（表記ゆれは不可。全角/半角に注意）
3. チーム能力：6項目すべて存在し、各1〜10の整数、**合計＝36**
4. 状況別指示が3個以下で、条件・変更項目がすべて定義済みの語彙である
5. 切り札が1つだけ指定されている
6. チーム名が両チームで重複していない（重複時は片方に「FC」を付けて続行）

**チェックに通らないファイルでは試合を開始できない。** これにより
「自由に書けるが、ズルはできない」を機械的に保証する。

## パース仕様（実装者向けメモ)

- 見出し行 `## セクション名` でセクションを切り替える
- セクション内の `キー: 値` 行（全角コロン `：` も許容）と `- IF ...` 行のみ解釈する
- それ以外の行（自由記述・空行・コメント）はすべて無視する
- 値の前後の空白はトリムする。キーは上記の日本語名で照合する
